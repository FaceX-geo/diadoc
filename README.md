# Локальный архив Диадока

Архив хранится на этом компьютере: SQLite, неизменяемые оригиналы и подписи, история версий и локальная HTML-страница поиска. Сборщик работает через открытую авторизованную вкладку Safari. Он читает DOM и нажимает штатные кнопки; интеграционный API, скрытые HTTP-эндпоинты, cookies и токены не используются.

## Установка

Нужны macOS с Safari, авторизованная вкладка Диадока, Python 3.10+ и свободное место для архива. Загрузки Safari должны сохраняться в `~/Downloads`: эту папку отслеживает захватчик. Во время сбора Mac должен оставаться разблокированным. Node.js нужен только для проверки синтаксиса JavaScript.

```sh
git clone https://github.com/FaceX-geo/diadoc.git
cd diadoc
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
./scripts/run-python scripts/archive.py status
```

`scripts/run-python` сначала выбирает `.venv`, затем установленный Python из Codex, затем системный `python3`. Для двух последних вариантов `pypdf` должен быть установлен в выбранном Python. Все команды ниже выполняются из корня репозитория.

## Что входит в репозиторий

- `AGENTS.md` — правила работы агента, согласование обновления и проверка полноты.
- `scripts/collector.js` — основной сборщик через интерфейс Safari.
- `scripts/archive.py` — локальная база, импорт, проверка, HTML-индекс и подготовка запуска.
- `scripts/capture_downloads.py` и `scripts/ingest_captured.py` — приём и импорт штатных загрузок.
- `tests/test_archive.py` — проверки логики архива.
- `diadoc-local.js` — ранний прототип чтения одной страницы; для полного архива использовать основной сборщик.

Копия репозитория содержит инструменты и инструкции. Сам архив создаётся локально. Актуальное состояние проверять командами `status` и `verify`: HTML-индекс различает считанный реестр и фактически сохранённые файлы. Контрольную точку конкретной загрузки хранить в `archive/resume-state.json`, не в общих инструкциях.

## Где находятся данные

- `archive/index.html` — локальный поиск, фильтры, статусы, даты из реестра и ссылки на оригиналы/подписи.
- `archive/archive.sqlite3` — документы, история метаданных, версии, файлы, контрольные суммы, проверенные партии и проходы реестра.
- `archive/documents/<направление>/<documentId>/<версия>/` — комплекты с читаемыми именами файлов.
- `archive/objects/` — содержимое файлов по SHA-256. В папках документов находятся жёсткие ссылки; одинаковые файлы физически не дублируются.
- `archive/manifests/` — снимки реестров и состав каждой партии.
- `archive/raw/` — исходные ZIP, которые удалось сохранить до автоматической распаковки Safari, и их квитанции.
- `archive/launch.js` — сформированный код запуска с перечнем уже проверенных документов. Перед новым разрешённым обновлением сформировать заново.

Архив, база, данные запуска и примеры исключены из Git. В оригиналы и подписи не вносятся изменения. Для файлов, автоматически распакованных Safari с неверной кодировкой имён, восстанавливаются имена; содержимое проверяется побайтно по SHA-256. Проверка целостности не является криптографической проверкой электронной подписи.

## Команды

Команды работают с архивом этого проекта:

```sh
./scripts/run-python scripts/archive.py status
./scripts/run-python scripts/archive.py verify
./scripts/run-python scripts/archive.py build-index
./scripts/run-python scripts/archive.py make-launch
```

Просмотр `archive/index.html` не требует Диадока или интернета. Для браузерного предпросмотра также можно запустить локальный сервер, доступный только этому компьютеру:

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory archive
```

## Первоначальная загрузка и продолжение после остановки

Прямой запрос пользователя собрать или обновить архив разрешает эту загрузку и её продолжение после остановки. Для новой задачи без такого запроса сначала задать вопрос из `AGENTS.md`.

1. Разблокировать Mac. Проверить текущую вкладку Диадока, выбранную организацию, состояние сборщика и незавершённые загрузки Safari.
2. Сначала импортировать уже завершённые партии, чтобы не скачивать их повторно. Не считать сообщение сайта «Архив скачан» доказательством наличия файлов на диске.
3. Запустить локальные процессы приёма и импорта в двух отдельных терминалах (перед запуском убедиться, что такие процессы уже не работают):

   ```sh
   ./scripts/run-python scripts/capture_downloads.py
   ./scripts/run-python scripts/ingest_captured.py
   ```

   Оба процесса работают до остановки через `Ctrl+C`; завершать их после импорта последней партии. Не запускать параллельно выгрузки нескольких организаций или разделов: захватчик связывает загрузку с последним манифестом партии.

4. Выполнить `make-launch`. Проверенные неизменившиеся документы попадут в список пропуска; отсутствующие, изменившиеся и повреждённые — в кандидаты на загрузку.
5. В Safari открыть нужный раздел с первой страницы без ограничивающих фильтров, дождаться строк и открыть «Разработка → Показать консоль JavaScript».
6. Вставить содержимое `archive/launch.js`. Альтернатива — выполнить короткий загрузчик ниже и выбрать локальный JS-файл через появившееся поле. Он читает файл локально через FileReader/File.text и не отправляет его на сервер.
7. Кнопка «Считать весь реестр раздела» обходит все страницы и сохраняет JSON. Кнопка «Собрать архив раздела» выбирает только недостающие/изменившиеся комплекты и скачивает по 50, используя «Документооборот целиком».
8. После завершения входящих повторить для исходящих. Внутренние проверить отдельно; явно пустое состояние — корректный результат, временное отсутствие строк во время загрузки — нет.
9. Импортировать полные снимки реестра и проверить покрытие всех трёх разделов. Выполнить `verify`, сверить число документов с полными комплектами, обновить HTML-индекс.

Загрузчик локального файла для консоли Safari:

```js
var ddInput = document.createElement('input');
ddInput.type = 'file';
ddInput.accept = '.js';
ddInput.onchange = async () => {
  (0, eval)(await ddInput.files[0].text());
  ddInput.remove();
};
document.body.append(ddInput);
```

После выполнения нажать появившуюся кнопку выбора файла и выбрать **собственный** `archive/launch.js`. Если консоль не получает ввод, проверить, не открыт ли модальный диалог Диадока. По завершении или ошибке сборщик оставляет состояние и JSON-контрольные точки; источник истины о сохранённых файлах — локальная база после проверки.

## Импорт файлов

Захватчик отслеживает только штатные ZIP с именами `Diadoc.Documents.*`, проверяет ZIP/CRC и сохраняет партию с её манифестом. Импортёр читает протоколы передачи PDF и связывает комплект с точным `documentId`, а не с похожим названием. При несовпадении ожидаемых идентификаторов партия не отмечается полной.

Ручной импорт завершённой партии:

```sh
./scripts/run-python scripts/archive.py import-batch /путь/к/dd-batch-....json /путь/к/Diadoc
./scripts/run-python scripts/archive.py import-batch /путь/к/....capture.json /путь/к/....zip
./scripts/run-python scripts/archive.py import-index /путь/к/dd-index-....json
```

Safari может автоматически распаковать ZIP быстрее, чем захватчик его сохранит. В таком случае использовать соответствующую распакованную папку `Diadoc` / `Diadoc N` вместе с точным манифестом партии; проверка протоколов не позволит импортировать папку от другой партии. Этот способ проверен на реальной партии.

Одно штатное скачивание ограничено **50 документами**. «Выбрать все во входящих» выбирает весь раздел, но снять это ограничение не позволяет; сборщик использует постраничные партии.

## Последующие обновления

Правило согласования закреплено в `AGENTS.md`: перед новой задачей спросить, подтянуть новые данные или работать с текущим архивом. Прямой запрос «обнови/догрузи» уже является согласованием. Расписание и безусловная фоновая синхронизация не создаются.

Сборщик сравнивает устойчивые поля реестра. Временные счётчики внутри строк и относительное отображение даты не должны вызывать повторные загрузки. Уже сохранённые неизменившиеся комплекты пропускаются. Для изменившегося документа запрашивается новый полный комплект; предыдущая версия остаётся, совпадающее содержимое дедуплицируется. Это консервативная сверка по видимым метаданным: изменения, никак не отражённые в реестре, потребуют отдельной проверки карточек.

Не считать отсутствие документа в очередной выборке командой на удаление из архива. Для восстановления повреждённых файлов `make-launch` исключает затронутые документы из списка пропуска; `requeue-damaged` также явно помечает их ожидающими восстановления. Невосстановленные ошибки всегда видны в `verify`.

## Проверки реализации

```sh
./scripts/run-python -m unittest discover -s tests -v
node --check scripts/collector.js
./scripts/run-python scripts/archive.py verify
```

Проверены: дедупликация метаданных, сохранение истории, отличия статуса, пропуск визуальных счётчиков, непрерывность полного прохода, пустое состояние и защита путей. Импорт реальной партии и проверка её файлов прошли успешно. Полный автоматический проход всех партий и всех трёх разделов пока не проверен до конца. При изменениях интерфейса Диадока могут потребоваться правки DOM-селекторов; метаданные без проверенных комплектов не считаются завершённым архивом.
